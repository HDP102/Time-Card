Here’s everything for both rulesets.

Ruleset 1: Production

Create it:

Go to Segmentation > All Policies and click Add, then pick the ruleset option.
Name: ICS_GoAlert | Production
Scope: ICS_GoAlert + Production
Pick both from the dropdown. If it only offers “New Label”, look under Labels like you did for FireMon.
Don’t pick ICS_GOALERT or ICS_goalert.
Save.

Add 3 allow rules:

3	Extra-Scope	R: Server + A: Tableau - v10.4.3 (PCE_Local) + E: Production	PostgreSQL Database	PostgreSQL Database
Ruleset 2: Non Production

Create it:

Go to Segmentation > All Policies and click Add, then pick the ruleset option.
Name: ICS_GoAlert | Non Production
Scope: ICS_GoAlert + Non Production
Save.

Add 2 allow rules:

#	Rule type	Source	Destination	Service
1	Extra-Scope	R: Server + A: EMS - Event Management System + E: QA + E: Development	Server	HTTPS
2	Extra-Scope	A: Azure App Proxy Connector (PCE_Local) + R: Server + E: Production	Server	HTTPS
How to fill each field
Source: add all the listed labels to the one Source field, exactly as the Core rule shows them. These are the Core labels with the A: / R: / E: prefixes. Multiple E: labels in one rule means “any of these environments”.
Destination: the ICS role labels without a prefix: Server or PostgreSQL Database. Both are confirmed on the GoAlert resources.
Service: pick HTTPS or PostgreSQL Database from the Policy Services list, the same named services the Core rules use.
Rule action: Allow, the same as all the others.

Do not provision either ruleset.

Not carried over: Core rule 1 (R: Utility Server → R: Utility Server, DHCP-Client). GoAlert is PaaS and has no utility servers.

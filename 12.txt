Your Postman is empty. The screen Brindha shared was her own saved request, so you'll build one from scratch. It takes about two minutes. **Don't press Send until Hareesh gives you the QA test LAN ID**: this call really disables whoever is in the body.

1. **New request:** click the **+** next to the "Get data" tab.
2. **Method and URL:** change **GET** to **POST**, and paste
   `https://api-ch-d.nonprod.pge.com/mea-udn-proxy-api/v1/accountdisable`
3. **Token:** open the **Authorization** tab, set **Auth Type** to **Bearer Token**, and paste the token from `py mea_token_test.py --raw` into the **Token** box. Paste only the long string starting with `eyJ`.
4. **Body:** open the **Body** tab, choose **raw**, change the dropdown on the right from Text to **JSON**, and paste:
   ```json
   {"workflowArgs": {"users": "TESTLANID", "requestedBy": "H2PR", "certificationID": "NPS-FER-RECERT-2026"}}
   ```
   Replace `TESTLANID` with Hareesh's test account.
5. **Send**, then screenshot the response:
   - **200 with a `requestID`:** the end-to-end test passed.
   - **401:** MuleSoft rejected the token, so send Brindha the response.
   - **Anything else:** send it to me.

The token expires about an hour after you got it. If you get a 401 later on, run `--raw` again for a fresh one.

There's also a simpler route once you have the test LAN ID: `mea_disable.py` does all of this itself, and it tests the real script instead of Postman. Put the LAN ID in a file, set `DRY_RUN = False`, then run `py mea_disable.py --input test.csv`. Do you want steps for that instead?
